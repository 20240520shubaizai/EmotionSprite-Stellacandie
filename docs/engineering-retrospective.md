# 工程问题复盘

## 多实例导致静默数据丢失

R2 在双开后发现第一会话数据消失。根因不是 SQLite 单条 SQL，而是多个应用实例同时维护内存状态和数据库生命周期。修复是在用户 AppData 放置 `QLockFile`，第二实例明确提示并退出。验证覆盖锁保持、第二实例拒绝和数据生命周期。

## 删除记忆后仍被召回

最初删除只写 `deleted_at`，但 `memory_state`、RAG 和模型历史仍可能保留旧内容。修复把删除视为跨层失效事件：统一状态、过滤查询、触发索引重建，并在模型上下文中过滤被删除主题。测试要求即时、延时、重启和同义问法均不再召回。

## 提醒时间串线

“两分钟后提醒我”未被解析后进入待补充状态，下一条完整提醒被错误当成时间补充。修复包括中文时间归一化，以及先判断新消息是否构成独立动作，再决定是否补全旧意图。

## 运行中安装半更新

旧脚本在复制到正在使用的 Agent 文件时才失败，造成半更新。修复把进程检查前移到任何文件变更之前；标准安装器也在 `PrepareToInstall` 阶段阻止运行中安装。

## 发布目录出现开发数据库

Agent 同步层使用相对 SQLite 路径，工作目录又是应用安装目录，因此首次运行会生成 `agent_core_sync_dev.db`。修复由 C++ Supervisor 显式传入用户数据目录中的数据库 URL，并让 Agent 缺少配置时拒绝启动同步库，而不是静默写入当前目录。

这些问题说明：可靠性来自数据边界、状态机和发布流程的一致性，而不只是增加更多 AI 提示词。
