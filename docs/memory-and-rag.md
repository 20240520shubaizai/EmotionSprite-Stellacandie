# 记忆与 RAG

项目把“用户说过一句话”和“长期事实”分开处理。候选内容先经过事实类型、重要度、置信度、有效期和隐私等级判断，再决定是否进入长期记忆。

提醒和事件不是普通长期记忆：它们拥有时间、状态、送达、完成、归档和跟进策略。一次性会议不会因为重要而每天重复询问；“一定要提醒”则提高交付优先级而不是盲目提高永久记忆重要度。

## 删除一致性

删除使用软删除以支持审计和恢复，但 `deleted_at` 与 `memory_state` 必须一致。删除后会通知模型、刷新列表并使 RAG 派生索引失效；送入模型的历史上下文也会过滤被删除主题，避免出现“界面删了但 AI 仍记得”。

## 防虚构

精灵可在低频创意事件中明确讲故事，但不能把数据库中不存在的共同经历伪装成真实记忆。询问历史事实时，检索不到应表达不知道或请求重新告知。
