# 总体架构

Stellacandie 采用同一台 Windows 电脑上的分层客户端架构，而不是传统远程 C/S 游戏架构。

## Qt/QML 表现层

QML 负责窗口、控件、动画、聊天消息和功能页；C++ 对象通过属性、可调用方法、模型和信号槽暴露给 QML。界面不直接拼 SQL，也不保存 API Key。

## C++ 应用核心

`AppController` 负责协调 UI、状态、存储、Agent 与功能模块。Repository 和 Schema Migrator 隔离数据库细节；确定性的提醒创建、删除确认、同步白名单和状态约束保留在本地代码中。

## Python Agent Runtime

桌面程序启动一个只监听 `127.0.0.1` 随机端口的 Agent 子进程，并用高熵会话令牌鉴权。双方通过 HTTP/SSE 与结构化 JSON 通信。Agent 崩溃后由 Supervisor 限次重启，失败则回到离线状态。

## 数据层

SQLite WAL 保存用户事实、消息、提醒、状态、日记和模块数据。向量索引属于可重建派生数据。可选同步通过 Outbox 发送允许的实体到独立 HTTPS 服务，再由服务端使用 MySQL；关闭同步不会删除本地内容。

## 关键边界

- UI 不拥有事实数据；
- 模型输出不是直接可信命令；
- Agent 工具需要注册、分级和确认；
- 删除记忆必须同时影响存储、检索和上下文；
- 秘密记忆不能进入普通 Trace 或同步；
- 服务不可用时要明确失败，不能伪造成功。
